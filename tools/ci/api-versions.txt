# Kubernetes API versions mdapi-prod serves, passed to `helm template
# --api-versions` by tools/ci/render-bundles.py. `#` comments and blank lines
# are ignored. Refresh under the SAME commit as a KUBE_VERSION bump.
#
# WHY THIS FILE EXISTS
# `helm template` runs OFFLINE: `.Capabilities.APIVersions` is just {"v1"} and
# `--kube-version` does not touch it (it sets `.Capabilities.KubeVersion.Version`
# only). A chart that branches on `.Capabilities.APIVersions.Has` therefore takes
# its LEGACY branch here while Fleet's agent -- which renders against the real
# cluster -- takes the modern one. For anything Kubernetes has since REMOVED,
# that is a resource kubeconform has no schema for, so fleet-validate reports it
# as an unexcused coverage gap and the pipeline goes red.
#
# Measured 2026-10-06 on gitlab 10.4.1, the first chart in this repo to branch
# this way. Without this file it rendered 4 Ingress as extensions/v1beta1, 6 HPA
# as autoscaling/v2beta1, 7 PodDisruptionBudget as policy/v1beta1 and 1 CronJob
# as batch/v1beta1 -- 18 resources, none of them validatable, none of them what
# gets deployed.
#
# BOTH FORMS ARE LISTED, because charts test both and helm's `.Has` is an EXACT
# match, not a prefix one:
#   * `group/version`         -- e.g. `networking.k8s.io/v1`
#   * `group/version/Kind`    -- e.g. `networking.k8s.io/v1/Ingress`
# gitlab 10.4.1 tests the Kind form (`_ingress.tpl` and the PDB/HPA/CronJob
# templates). Verified by rendering the same chart with `-a networking.k8s.io/v1`
# alone, which still produced extensions/v1beta1 -- the version form is not enough.
#
# REFRESH: regenerate both sections from the cluster. The commands are the whole
# procedure; there is no hand-maintained content below this header.
#
#     kubectl --context mdapi-prod-direct api-versions
#     kubectl --context mdapi-prod-direct api-resources --no-headers \
#       | awk '{print $(NF-2)"/"$NF}' | sort -u
#
# ⛔ ROT RUNS ONE WAY ONLY, and the loud way is the safe one. A version the
# cluster GAINS but this file lacks makes a chart fall back to its legacy branch:
# the render is wrong, Fleet deploys the modern form, and fleet-validate fails
# loudly on the missing schema. A version the cluster LOSES but this file still
# claims is the dangerous one -- CI would then validate a render Fleet will not
# produce, silently. So when in doubt delete entries; never hand-add one.
#

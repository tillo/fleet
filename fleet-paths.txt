# Bundle directories that gitrepo/mdapi-prod renders, one per line.
#
# WHY THIS FILE EXISTS
# The GitRepo is NOT in git -- it lives only on the mgmt cluster
# (-n fleet-default gitrepo/mdapi-prod) and enumerates spec.paths explicitly,
# because a null paths renders an extra catch-all bundle that duplicates every
# file in the repo and sits against etcd's 1.5 MiB per-object limit.
#
# The cost of that is permanent and easy to forget: Fleet discovers NOTHING.
# On 2026-09-22 the falco/ bundle merged with a green pipeline and deployed
# nothing at all -- no bundle was created, while the GitRepo reported
# Ready=True, Stalled=False. lint.py now fails the MR instead.
#
# ADDING A BUNDLE
#   1. add its directory here
#   2. after merge, append it to the live GitRepo (APPEND, never regenerate):
#      kubectl --context mdapi-rancher -n fleet-default \
#        patch gitrepos.fleet.cattle.io mdapi-prod --type=json \
#        -p '[{"op":"add","path":"/spec/paths/-","value":"<dir>"}]'
#
# RULES
#   * Fleet RECURSES into every listed path, so never list a directory whose
#     ancestor is also listed -- it renders that bundle twice in one job and
#     the second write loses an optimistic-concurrency race, which stalls the
#     GitRepo and freezes bundling for the WHOLE repo.
#   * Both fleet.yaml and fleet.yml count.
#
